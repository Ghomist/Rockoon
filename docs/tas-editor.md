# TAS 编辑器（设计规格）

Rockoon 的试验功能：一个逐帧按键编辑器，以**独立窗口**打开（label `tas-editor`，同一个 `index.html` 带 `?window=tas`，`main.tsx` 据此只渲染 `TasEditorWindow` + 一份 `GlobalDialogHost`；开窗逻辑在 `src/services/tasWindow.ts`）。入口在侧边栏菜单：前后各一个分隔符、紧挨在「下载任务」上方，点一下开窗口、**不切换主窗口当前页面**（菜单项是 `action` 而不是 `route`）。窗口无系统边框（`decorations: false`，标题栏自绘 + `TitleBarControls`），一打开就最大化；已开着再点只是把它提到最前。

**入口开关**：设置 →「实验功能」→「TAS 编辑器」（偏好 `enableTasEditor`，**默认关**）。关着时侧边栏看不到入口（连同它后面那条分隔线）；`AppSidebar` 订阅这个偏好，切换后入口立刻出现 / 消失。侧边栏里的 `<button>`（TAS 入口、分组、外链、折叠）都带 `cursor-pointer`：Tailwind v4 的 preflight 把 button 的光标设回了 default，只有 `<Link>` 才自带手型。

**TAS 窗口自己挂了一份 `<Toaster/>`**（`main.tsx` 的 `?window=tas` 分支）：Toaster 原来只在主窗口的 `App` 里，编辑器里所有 `toast(...)`（先选关卡、先保存到 TAS 目录、Player.exe 没退干净、保存失败…）全都看不见。

**未保存的改动**：在列表里换文件、关编辑器窗口时，当前文件有未保存的改动就先问「保存 / 不保存 / 取消」（关掉对话框 = 取消；游戏在区域里时先把游戏窗口挪开，HTML 弹窗盖不住它）。关窗时先问这个，再问游戏怎么处置。

> 历史：第 7 轮曾改成应用内页面（路由 `/tas`），之后为了把游戏窗口摆进编辑器（见 §8.1）又改回了独立窗口。第 7 轮的验收项（§9 第 11 条）已作废。

目标是「像剪辑软件一样好用」，交互**不要**参考 BallanceTasToolbox（上游项目只用来确认文件格式）。

## 1. 文件格式（已实现，不要改）

`.tas` = 4 字节小端 int32（未压缩字节数）+ zlib 流；流内每帧 8 字节：

- `float32 LE deltaTime`（毫秒）
- `uint32 LE keystates`

位序固定（与界面轨道顺序无关）：bit0 ↑ / bit1 ↓ / bit2 ← / bit3 → / bit4 Shift / bit5 Space / bit6 Q / bit7 Esc / bit8 Enter。

数据层在 `src/tas/format.ts`：`TasFile` 类 + `parseTas()` / `writeTas()`（浏览器原生 `DecompressionStream` / `CompressionStream("deflate")`，无第三方依赖）。

**帧时长**：格式允许逐帧不同，但本编辑器只支持「全局统一」——所有帧共用同一个 deltaTime。修改帧时长即把全部帧写成该值（不支持变速 TAS）。默认 1000/240 ≈ 4.166667 ms（游戏固定 240Hz）。

工具栏只有一个「帧率(fps)」输入框：直接填 264 / 240 / 132 / 120 / 60 / 30（或任意正数），内部换算成 `1000/fps` 毫秒写进每一帧（264 fps = 1000/264 ≈ 3.787879 ms，132 fps = 1000/132 ≈ 7.575758 ms）；框里显示的就是当前 fps。

## 2. 视口与滚动

- 横向**不提供滚动条**，靠「缩放 + 平移」浏览。
- **缩放**：`W` / `S`（长按连续，键帽自己的速率 ≈ 2.4/s，见 `HOLD_ZOOM_PER_SEC`）、滚轮上下（无修饰键，约 1.25×/格）、工具栏 +/- 按钮、缩略图拖动边缘。**锚点 = 鼠标指针位置**（指针下的帧保持不动），都走同一套平滑插值动画（约 120ms）。
- **长按 W/S/A/D**：按下**立刻**按帧步进（`requestAnimationFrame` 循环里按 dt 算），不依赖系统按键重复，所以没有「初始延迟」。方向键只用于光标移动，不参与缩放/平移。
- **平移**：`A` / `D`（长按连续，速度 = 若干视口宽/秒）、`Shift` + 滚轮、滚轮横向分量、按住 `Space` 拖拽 / 中键拖拽。
- **缩放范围**：每帧 **0.02px ~ 64px**（默认 14px）。下限故意极小、基本等于“没下限”，因为低倍率会自动切进区块模式（工作量与可见帧数无关），所以缩到整个文件尽收眼底也不会卡。工具栏百分比在 <10% 时显示一位小数。
- 无限滚动：只渲染可见列（虚拟化）。可编辑总长度 `totalFrames = max(文件原有长度, 最后绘制帧 + 余量)`，绘制超出右端时自动增长；**保存时按 totalFrames 写**，不自动裁掉尾部空帧（裁尾要显式命令，因为尾部空帧也算时间）。
- 顶部刻度尺按**帧**标注（不按秒），但**大区以时间为基准：0.5 秒一个大区**。一个大区多少帧按当前**全局帧时长**折算：`tickFrames(cellW, frameMs)`（`BAND_SECONDS = 0.5`、常量在 `src/tas/viewport.ts`）—— `frameMs=10` → 50 帧，`=5` → 100 帧，`=20` → 25 帧。**改了全局帧时长要重算**。缩放很小、标签排不下时，把基准乘 `1/2/5/10/…` 放大（此时大区 = 0.5s 的整数倍，如 1s / 2s / 5s），保证相邻标签间距 ≥110px。标签格式 `50 (0.500s)` —— 帧号 + 空格 + 括号内时间（时间保留 3 位小数，≥60s 用 `1:23.456`）。次刻度取大区的 1/5 或 1/2（必须是整数帧；间距 <10px 就不画）。刻度尺是**粘顶**的（画在 canvas 顶部，不随纵向滚动）。
- 标签**右端会越过画布右边时整个不画**（刻度线照画）：被裁掉一半的标签比没有标签更难读。判定用 `ctx.measureText(label).width`，在 `src/tas/render.ts` 的刻度循环里（第 5 轮加的，之前会画到画布外被裁一半）。

### 2.1 打开文件 → 光标落在第一个有按键的帧

- 打开 `.tas` 后光标直接跳到 `firstPressedFrame(tas)`（`src/tas/editing.ts`：从 0 扫到末尾，返回第一个「9 条轨道任一位按下」的帧；全是空帧则返回 0），并用 `TasTimeline.reveal()` 让这一帧进入视野。
- reveal **不新写一套居中逻辑**：沿用既有行为（帧在视口里就什么都不做；否则滚到视口左侧约 30% 处；靠近末尾时由 `clampViewport` 兜住，不会贴到边缘外）。
- 时机：`TasEditorWindow` 里用 `pendingRevealRef` + `useEffect(…, [doc])`，等 `TasTimeline` 挂载并做完「换文件复位视口」之后再 reveal —— 否则会被那次复位盖掉（子组件的 effect 先于父组件执行）。

### 2.2 「当前帧」徽标与输入框

- **徽标**：刻度尺里、光标竖线旁边的一个小圆角胶囊 + 帧号文字（先描一圈深色再填白，和块帧数标签同一手法）。默认挂竖线右侧；右边放不下就翻到左侧，最后再钳进画布（贴左右边缘都不会被裁）。颜色走 `TasPalette.cursorBadge` / `cursorBadgeText`（明暗两套）。光标竖线本身仍由原来的那段逻辑画，徽标不重复画线。
- **输入框**：工具栏「帧率」右边（`tas.currentFrame`，zh「当前帧」/ en "Frame"）。实时显示当前帧；输入帧号后 `Enter` 或失焦就跳过去（`clamp(0, frameCount-1)` + 设光标 + `reveal`），非整数输入（`abc`/空）恢复成当前值。
- 实现要点：受控 input 会和打字打架，所以用**本地 state + 焦点态** —— `value = 聚焦 ? 本地文本 : String(cursor)`。聚焦时以输入框为准；失焦/提交后一律由 cursor 派生，于是点击、方向键、`Tab`、`Home`/`End` 改光标时输入框立刻跟着变。宽度只留 5 位数字（`w-16`），样式与「帧率」那个 `Input` 一致。

## 3. 网格与配色

- 纵向网格线、横向网格线、**分区** 三个开关**互相独立**（状态持久化，见 `src/tas/prefs.ts` 的 `vGrid` / `hGrid` / `bands`）。
- 「分区」：背景按**大区（0.5 秒）**交替着色（深浅两色，区间边界线略深）；大区的宽窄只跟全局帧时长与缩放有关。第 4 轮从「纵线」里**拆出来单独开关**（以前关纵线会把大区一起关掉）；第 5 轮把大区基准从「固定帧数阶梯」改成「0.5 秒折算帧数」。
- 按键方块：同一轨道上连续的帧合并成一个**小圆角矩形**（胶囊状），最小可视宽度 4px；颜色按按键区分（参考现有 `KEY_META`），明暗两套主题都要好看。
- **块帧数**：每个胶囊在**起点**用 10px 白字（描一圈深色，保证在任意按键配色上都读得清）标出这一段有多少帧，如 `51 帧` / `51 frames`（文案走 i18n 的 `tas.blockFrames`，由 `TasEditorWindow` 传 `blockLabel` 给 canvas）。文字（含左右各 5px 内缩）在块里放不下、行高 <16px、低倍率区块模式或左边缘被视口截断（帧数会算错）时都不写。
- **低倍率区块模式**（`cellW < RUN_CELL_W`，即 4px/帧，常量在 `src/tas/viewport.ts`）：只保留合并后的胶囊 + 刻度尺 + 选区/光标，跳过纵向网格线与悬停格（在这个倍率下只有零点几像素宽）。渲染工作量与**可见帧数无关**，所以任意倍率下的 DOM/canvas 工作量都是有界的。
- 其它着色：当前帧列高亮、悬停格提示、选区半透明覆盖、拖动中的块半透明跟随。

## 4. 交互（核心）

| 操作 | 行为 |
| --- | --- |
> **统一规则：** 有选区就作用于选区（方向键搬动、`Delete` 清空、时长框改帧数、复制/剪切/粘贴），没有选区就作用于当前帧。任何鼠标模式下都生效的：`Alt`+拖、`Space`/中键拖、滚轮缩放、`W`/`S`/`A`/`D`。

| `1` / `2` / `3` / `4` | 切换鼠标模式：选择（默认）/ 绘制 / 填充 / 录入（工具栏上行一个分段控件，四段都带 `1`-`4` 角标） |
| 左键单击 | **选择模式**：单击一段按键 = 一次性选中**这一整段**；单击空格 = 选中这一格（时长 0） |
| 左键拖拽（行内） | **选择模式**：框选这一段的一部分（不许跨行；只考虑有按键的帧，自动收拢到有按键处） |
| 方向键 | **选择模式**：直接搬动选中的那一段（`←`/`→` = 挪帧、`↑`/`↓` = 换轨道） |
| 工具栏「按键时长」 | **选择模式**：显示选中那一段的帧数并实时修改（`0` = 删掉、空选上 `> 0` = 新建按键） |
| 左键点击 / 拖拽 | **绘制模式**：绘制（**固定语义**，画过的地方不会因为再点一下就被擦掉），按住连续涂 |
| 右键点击 / 拖拽 | **绘制模式**：擦除（固定语义），按住连续擦 |
| 左/右键拖拽 | **填充模式**：拖出一个矩形，左键松手 = 矩形内全部置位，右键松手 = 全部清除（拖动过程有矩形预览，松手才提交，算一次撤销单位） |
| 左/右键拖拽 | **录入模式**：在时间轴上拖出一段时间（纵向盖满全部轨道），随后映射键一次性覆盖这个选区 |
| `Shift` + 拖拽 | **绘制/填充模式内**：修改**只发生在起点那一行**（鼠标纵向跨到别的轨道也不写它们，横向仍照常推进帧）。录入模式里 `Shift` 仍是录入键 |
| `Alt` + 左键拖拽 | 抓住已填充的方块拖动；默认抓取**该轨道上横向连续**的一整块（可跨轨道移动）；**若已经用选择模式选中了其中一段，则只搬这一段**。四种模式下都可用 |
| `W` / `S` | 放大 / 缩小（长按连续，锚点 = 鼠标指针） |
| `A` / `D` | 左右平移（长按连续） |
| 滚轮上下 | 缩放（锚点 = 鼠标指针）；`Shift` + 滚轮 = 左右平移 |
| 方向键 | 光标左右移动（`Shift` + 方向键 = 把选区扩到光标处） |
| `Tab` / `Shift+Tab` | 下一帧 / 上一帧；**有选区时 = 整个选区平移一帧**（数据跟着走，锁定轨道不动） |
| `Space` 或中键拖拽 | 按住期间临时平移视图（剪辑软件习惯；录入模式下 `Space` 是录入键） |
| `Esc` | 取消选区 / 取消当前拖动（录入模式下 `Esc` 是录入键） |
| `Delete` / `Backspace` | 有选区 = 清空选区内容；**无选区 = 清空当前帧的按键**（锁定轨道不动） |
| `F2` | （已删除：录入从独立开关变成鼠标模式 `4`，见 4.1） |
| `Ctrl+Z` / `Ctrl+Shift+Z` | 撤销 / 重做 |
| `Ctrl+C` / `Ctrl+X` / `Ctrl+V` | 复制 / 剪切 / 粘贴（粘贴到光标处；有选区时覆盖，`Ctrl+Shift+V` 插入式粘贴） |
| `[` / `]` | 跳到上 / 下一个**按键段的边缘**（所有轨道一起看、取帧号最近的；段起点与段末帧都算边缘；`Shift` = 把选区一起扩过去） |
| `+` / `-` | 缩放（`W`/`S` 与工具栏按钮同义） |
| `Ctrl+S` / `Ctrl+Shift+S` | 保存 / 另存为… |
| 右键（**选择 / 录入**模式） | 弹出上下文菜单：选中整段 / 跳到这一帧 / 复制 / 剪切 / 粘贴 / 删除选中的按键（右键落在已有选区里就保持选区，否则先像左键那样选中）。**绘制 / 填充模式**里右键仍是擦除 / 清除 |
| `Home` / `End` | 跳到首帧 / 末帧 |
| 单击轨道头拖动 | 上下调整轨道顺序（持久化） |

绘制语义细节：

- 三种鼠标模式下 `Alt` 拖块、`Space`/中键拖动平移、滚轮缩放、`W`/`S`/`A`/`D` 都照旧。
- 左键只负责「画上」、右键只负责「擦掉」，**没有画笔/擦除模式切换**，也没有「点一下取反」。
- `Alt` 拖拽移动的块若与已有内容重叠，重叠处按「后写入者覆盖」处理。
- 撤销栈：**按操作整体入栈**（一次拖拽 / 一次填充矩形 / 一次录入按键 = 一步），用帧数据快照实现（19,600 帧 ≈ 157KB，上限 120 步）。

### 4.1 鼠标模式四选一（`1` / `2` / `3` / `4`）

工具栏里紧挨着「保存 / 另存为」的一段四选一按钮（`aria-pressed` 标当前模式），模式**不持久化**，每次打开默认「选择」：

| 模式 | 快捷键 | 左键 | 右键 |
| --- | --- | --- | --- |
| 选择 | `1` | 单击选中整段 / 行内拖动框选 | （同左键，右键不参与） |
| 绘制 | `2` | 按住连续画 | 按住连续擦 |
| 填充 | `3` | 拖出矩形，松手全部置位 | 拖出矩形，松手全部清除 |
| 录入 | `4` | 拖出一段时间（= 选区，纵向盖满 9 轨） | 同左键 |

- **填充**：拖动过程显示**矩形预览**（置位 = 绿、清除 = 红），松手才写数据并算**一次撤销单位**；锁定轨道跳过。
- **录入**：原来靠 `F2` 单独开关，现在改成**模式 `4`**（工具栏那个 F2 按钮已删掉，原来「选区」的位置就是它）。录入只在这个模式下发生，见 4.2。
- **选择**：默认模式，见 4.5。

### 4.2 录入模式（`4`）

「按键覆盖当前帧」的工作方式。开启后，**9 个映射键 `↑ ← → ↓ Shift Space Q Enter Esc` 一律解释为录入**，不再触发原有快捷键（方向键不再移动光标、`Space` 不再临时平移、`Esc` 不再取消选区、`Shift` 不再是单行约束、`Enter` 不再走默认行为）。`W`/`S`/`A`/`D` 不在映射表里，**缩放/平移照旧可用**；鼠标模式（`1`/`2`/`3`）在录入模式下也能切。

- 光标移动改用 `Tab` / `Shift+Tab`（以及 `Home`/`End`、鼠标点击）。
- **覆盖语义 = 完全覆盖**：在某一帧上**第一次**按键时，先把该帧上所有**非锁定**轨道的按键清空，再置位按下的键；同一帧内继续按键是**累加**（先 `↑` 再 `→` = 该帧 `↑+→`）。光标离开该帧即结束这一轮，回到该帧再按又是一轮新的覆盖（`src/tas/editing.ts` 的 `coverRange()`）。
- 有选区时，按键**一次性覆盖选区内所有帧**。
- 退出：切回其它鼠标模式（`1`/`2`/`3`）。`Esc` 在模式内是录入键，不用于退出。模式状态**不持久化**，每次打开默认「选择」，需要录入再按 `4`。
- 状态栏右侧一直显示**当前帧的按键 chip 列表**（按 `KEY_META.short`，与轨道同色的小圆点），一眼看出这一帧现在是什么。

### 4.3 轨道锁

每条轨道头的**轨道名前**有一个锁图标按钮（`aria-label` = 锁定/解锁轨道，`aria-pressed` 表示状态），点击切换：

- **锁定 = 该轨道完全不可编辑**：左键绘制、右键擦除、录入覆盖、`Alt` 拖块、选区删除/平移、粘贴全都跳过它（`clearRange` / `pasteClip` / `coverRange` / `shiftRange` / `paintOne` 都带 `locked` 参数）。
- 视觉：图标高亮为琥珀色 + 该轨道头降透明度 + canvas 里该行盖一层蒙版（`TasPalette.lockVeil`）。
- 锁状态写进编辑器偏好（`src/tas/prefs.ts` 的 `locked`）。
- 已知边界：**插入式粘贴**（`Ctrl+Shift+V`）会整体右移时间轴，锁定轨道里的既有数据位置也会被动跟着移，只是不会被写入剪贴板内容。

### 4.4 选区 = 一段时间

选区是 `{f0, f1, t0, t1}`，但 UI 上只做「一段时间」：`t0 = 0`、`t1 = 轨道数 - 1`，纵向盖满全部轨道。

- 建立：**录入模式（`4`）** + 拖拽（纵向盖满全部轨道），或 `Shift` + 方向键 / `Home` / `End`；**选择模式（`1`）**里的选区不同 —— 它是单轨上的一段（单击整段 / 行内框选），见 4.5。
- 视觉：整列高亮 + 起止帧两条竖线，标题栏保留「选区 N×M」提示。
- 用途：录入覆盖（4.2）、`Delete` 清空、`Ctrl+C/X/V`、`Tab` / `Shift+Tab` 整段平移一帧。
- `Alt` + 左键拖块（拖动连续段）保持不变，与选区互不影响。

### 4.5 选择模式（`1`，默认）

单击 = 选中一段（同一轨道上横向连续的一整块）；单击空格 = 选中这一格（时长 0）。

- **框选**（同一行内拖动）：只考虑这一行有按键的帧 —— 锚点那格有按键就取包含锚点的整段与该区间的交集（= 框住整段的一部分），锚点是空格就取区间内离它最近的那段，区间里一点按键都没有则原样保留（时长 0，可用来新建）。不许跨行。
- **方向键**：直接搬动选中的那一段（`←`/`→` 挪帧、`↑`/`↓` 换轨道，会覆盖目标位置的原有内容，锁定轨道就整段不搬）；切到空选区上只挪选择位置，不写数据。
- **`Alt` + 拖动**：按住选中的那一段里的任意一格拖动 = **只搬框出来的这一小段**（选区跟着走，松手后还能继续拖或改时长）；Alt 按在选区外仍然是搬「横向连通的一整块」。
- **工具栏「按键时长」**：显示选中那一段的帧数，输入即改（`setRunLength`：只在选区内操作 —— `0` = 删掉这一段，所以框住一段中间改成 `0` 会在那儿挖个空档；空选上改成 `> 0` = 从此处新建按键，超过选区长度就往右伸长）。只在选中单行时可用。
  - 选中后**自动聚焦**到这个框，可以直接打字（不用再点一下）；数字保持全选，所以接着打字是「整体替换」。
  - 框上**滚轮 = ±1 帧**（按住 `Shift` = ±10），滚完数字仍是全选状态，可以连着滚。
  - 聚焦期间只有数字 / 退格 / `Delete` / `Ctrl+*` 归输入框，方向键、字母（`W`/`S`/`A`/`D`）、`Tab`、`空格` 照旧归编辑器；`Esc` 或点画布可以离开这个框（想用 `1`~`4` 切模式、用 `Delete` 清空选区，得先离开）。
- 纯逻辑自测：`.local-logs/tas-runlength-test.ts`。

### 4.6 底部说明区与帮助

- 工具栏下面那一行修饰键提示已**移到底部固定的说明条**：**内容跟着当前鼠标模式变**（只显示本模式最相关的 3-4 条：选择 = 单击选中整段 / 行内拖框选 / 方向键搬动；绘制 = 按住画 / 按住擦 / 拖动只改起点那一行；填充 = 拖矩形 / 左键置位 / 右键清除；录入 = 拖出时间段 / 映射键覆盖写入），末尾固定跟一条「缩放；Shift + 滚轮 = 左右平移」（工具栏 —— 现在放在上左的编辑面板里，空间不够会自动折行 —— 也拆成了两组：**上行** = 文件（保存 / 另存为 / 一键播放 / 裁掉尾部空帧）+ 编辑（撤销 / 重做）+ 鼠标模式分段控件；**下行** = 帧参数（当前帧 / 按键时长 / 帧率）+ 视图（纵线 / 横线 / 分区、缩放 −/%/+ / 适配）+ 右端的「本帧按键」chip。文件级的一次性命令放上行，是为了让下行在常见窗口宽度下不折行），键帽用 `kbd` 样式（等宽 + 边框 + 底色，明暗都好看），实现在 `src/views/tas/TasHints.tsx`。
- 说明条右端有 `?` 帮助按钮（`aria-label` = 帮助），点开模态窗放**完整**快捷键表 + 鼠标模式 / 单行约束 / 录入模式 / 覆盖语义 / 轨道锁 / 自动备份的说明。模态走项目既有的 dialog store（`dialog.create`），所以弹窗由 App 里那份 `GlobalDialogHost` 渲染。

### 4.6.1 说明条（第 N 轮重做）

- 左端：**当前鼠标模式**（名字 + 切换键）；中间：这个模式最常用的 3~6 条 │ 分隔线 │ 任何模式都通用的视图操作（缩放 / 平移 / 拖动视图 / 跳到段边缘 / 撤销）；右端「全部快捷键」打开帮助模态。窄的时候自动折行。
- 一条说明 = 几种按法（`/` 隔开）+ 每种按法里同时按的键（`+` 连）+ 说明文字，例如 `滚轮 / W / S 缩放`、`Shift + 拖 只改起点那一行`。
- 之前「有点糊」的原因：键帽统一用了 `font-mono` + 10px，而「单击」「滚轮」这种中文键名在等宽字体里没有字形，回退成别的字体后发虚。现在只有 ASCII 键名用等宽字体，中文键名用正文字体；键帽 11px、带底边，说明文字 12px、接近正文颜色。

### 4.6.2 鼠标指针

画布的指针由 `TasTimeline` 的 `updateCursor()` 统一决定（只在 rAF 悬停变化、按下 / 松开、Space / Alt 变化、换模式 / 锁轨道时算，不在每个指针事件里算）：

| 情况 | 指针 |
| --- | --- |
| 中键 / Space 拖动平移、Alt 拖块中 | `grabbing` |
| 按住 Space、Alt 悬停在一段按键上（可以拖走） | `grab` |
| 刻度尺上（拖 = 移动光标）及拖动中 | `ew-resize` |
| 锁定的轨道 | `not-allowed` |
| 选择模式悬停在按键上 / 空白处 | `pointer` / `default` |
| 绘制、录入 | `crosshair` |
| 填充（含拖动中） | `cell` |

轨道头拖动排序是 `grab` / `grabbing`，缩略图的视窗框是 `grab`、边缘是 `col-resize`、空白处（点一下跳过去）是 `pointer`。

### 4.7 自动备份

保存（含「另存为」覆盖已有文件）之前，先把目标文件原样复制一份到同目录 `<文件名>.tas.bak`（已存在则覆盖）。失败只 `console.warn`，**不阻止保存**。实现在 `TasEditorWindow.save()` 里用 `backend.exists()` + `backend.copy()`。

## 6. 界面布局

```
┌ 标题栏（自绘，整条可拖拽）：TAS 编辑器 · 文件名 · 帧数 · 时长 · 当前帧 · 保存状态 · 选区 │ 窗口按钮 ┐
├────────────────────┬──────────────────────────────┬────────────────────┤
│ 左：文件列表         │ 中：游戏区域                   │ 右：控制面板          │
│ （筛选 + 元数据）     │ 宽 = 分辨率 / dpr（1:1，居中）  │ 回放 / 文件 / 编辑 /   │
│ flex-1 basis-0      │ 上面不放任何控件               │ 帧 / 视图             │
│                    │                              │ flex-1 basis-0       │
├════════════════════╧══════════════════════════════╧════════════════════┤
│ 下半区：刻度尺（粘顶）/ 轨道头 │ 网格区（canvas）/ 缩略图                                  │
│ 说明条：[当前模式 + 键] 本模式常用几条 │ 通用视图操作                     [全部快捷键]      │
└──────────────────────────────────────────────────────────────────────────┘
  （上下、左右都没有可拖的分栏：游戏区域按分辨率 1:1 固定，两侧等宽）
```

- **上半区三栏**：左 = 文件列表、中 = 游戏、右 = 控制面板。**左右两栏等宽**（都是 `flex-1 basis-0`，平分游戏以外的宽度），游戏列宽度恰好等于分辨率 / dpr，所以游戏始终居中。左右、上下都没有可拖的分栏（偏好里的 `leftW` / `fileW` / `layout` 已删）。两侧各不到 `SIDE_MIN_W = 320px` 时「回放」里提示窗口太小。控制面板**全部用 shadcn 组件**（不要自己写 UI）：每组一个 `Card`（`CardTitle` 带图标，状态 / 撤销重做放 `CardAction`），字段是 `Label` + `Input` / `Select`，鼠标模式是单选 `ToggleGroup`，纵线 / 横线 / 分区是多选 `ToggleGroup`，「操作游戏」是 `Toggle`，游戏状态 / 保存状态 / 本帧按键是 `Badge`，窗口太小的提示是 `Alert`；始终一纵列。`toggle` / `toggle-group` / `alert` 是用 shadcn CLI 加的（CLI 生成的 `cn` 导入要改成 `@/lib/utils`，它会顺手装一个无关的 npm 包 `cn`，要删掉）。
- **游戏区域上方没有顶栏了**（原来的 项目名 / 分辨率 / 关卡 / 速度 / 播放 都搬进了「回放」分区），**也没有内边距**：游戏画面贴着分栏线和窗口边缘，区域尺寸 = 分辨率 / dpr；空态只显示一句提示和当前分辨率。
- **文件列表**（上左1）：顶上一个筛选框（按文件名、不区分大小写，`Esc` 清空），按文件名自然排序。每项显示去掉扩展名的项目名 + 一行元数据 `19,600 帧 · 240 fps · 1:21.667`：列表一变就把还没解析过的文件挨个 `parseTas` 一遍，按「文件名|大小」缓存；保存后丢掉该文件的缓存（内容变了但大小可能没变）。读不出来的显示「读不出来」。

- **没有可拖的分栏**：上半区高度 = 游戏区域高度（分辨率 / dpr），固定不能拖 —— 拖高了游戏画面上下有黑边、拖矮了画面被剪掉。窗口太矮时给时间轴留出至少 200px，游戏区域被剪掉一截并在「回放」里提示。偏好里不再存任何布局尺寸（`layout` 已删）。
- **游戏区域永远是分辨率 1:1**：物理像素 = 所选分辨率，CSS 尺寸 = 分辨率 / `devicePixelRatio`。窗口大小或 dpr 一变，就让 `leftW` / `topH` 去吸收多余空间（上半区高度收成「刚好装下区域 + 顶栏」，下半区至少留 `TIMELINE_MIN_H = 200px`），黑框本身不跟着缩放。窗口装不下时顶栏出现「区域太小」的提示（游戏窗口会被裁掉一截）。
- 分辨率下拉在 `GAME_RESOLUTIONS`（4:3 为主；宽屏几项要游戏配置里开 UnlockWidescreen），写进偏好 `gameWidth` / `gameHeight`。
- 轨道头**横向冻结**（平移时不动），纵向与网格同步滚动/平移。
- 轨道头显示按键名 + 图标即可，**不要额外的描述文字**。
- 深浅色主题都要正常（`useDarkMode()` 已存在）。

## 7. 性能要求

- 网格用 `<canvas>` 渲染（按 `devicePixelRatio` 放大），不要用 DOM 逐格渲染。
- 每帧重绘只做可见列；拖动绘制时用 `requestAnimationFrame` 合批。
- 缩放/平移/长按缩放的平滑动画和长按键步进**共用一个 rAF 循环**，不要各排各的（会互相叠加、越转越快）。
- 1920px 宽、每帧 14px、9 条轨道下拖动绘制应稳定 60fps；缩到 0.02px/帧时走区块模式，可见工作量同样有界。
- **指针事件只记位置，不在事件里做命中测试/重绘**：真实鼠标常在 1000Hz 以上，事件级命中测试等于白烧 CPU，会把旁边跑着的游戏挤掉帧。`pointermove`（非拖拽）只把坐标丢进 `pendingHover`，命中测试与重绘都在 rAF 里做一次（同一格重复移动不重画）。
- 回放期间游戏进程用 `HIGH_PRIORITY_CLASS` 启动（`process.execute` 的 `highPriority`）：游戏是单线程跑满的，别让编辑器跟它抢 CPU。

## 8. 一键播放（BallanceTAS 2.0）

工具栏「保存 / 另存为」右边的 `Play` 按钮：把当前文件设成 BallanceTAS 的启动项目，然后启动游戏。

> **目录**：BallanceTAS 2.0 把项目放在 **`ModLoader/TAS/`**（旧的 TASSupport 用 `TASRecords/`，已废弃）。左栏只列该目录下的 `*.tas`，`temp/` 子目录（BallanceTAS 的工作目录）不列；目录不存在就是空列表，不报错。
>
> **配置**：`ModLoader/Configs/BallanceTAS.cfg`，是 mod 自己的文件（不是 Rockoon 的），所以**必须**走 `backend.readModConfig` / `backend.saveModConfig` —— 它们带 `description` / `categories`，是唯一能保住分区、条目描述与注释的读写途径。纯数据（「要改哪几项」）在 `src/tas/play.ts`。

点击后的顺序：

0. **先确定关卡**：BallanceTAS 2.0.0-beta.1 起，录像在启动时只会被「armed」，要等关卡载入才开始播；而 `.tas` 里没有关卡信息。所以游戏区域顶栏有个「关卡」下拉（第 1~13 关），按项目名记在偏好 `projectLevels` 里；没选过就用 `inferLevel()` 从文件名猜（`SR_01_…` / `Level_03` / `L5-…` / `lv12` / `07_…`，范围外或猜不出 = 没有）。没有关卡 → `toast`「先选关卡」并中止（不保存、不写配置）。
   **两个播放按钮**：「播放」从**编辑器当前帧**开始看（光标帧，夹在录像范围内），「从头播放」从第 0 帧开始。区别只在 `TAS.SkipRenderUntilFrame`：回放照常从第 0 帧跑物理（结果必须和从头放一致），只是第 N 帧之前不渲染；RockoonIO 发现连续 2 帧没渲染就不限速（§8.3），于是一路快进到第 N 帧，再按设定速度播。中间那个大播放按钮、左侧面板的「一键播放」都是「从当前帧」。实测：N = 6000 时快进段约 5500~6500 fps、约 1 秒走完，随后稳定在 240。
1. 当前文件必须已经在 `ModLoader/TAS/` 里（用「另存为」存到别处的文件不行）。有未保存改动先走既有保存逻辑（含 `.bak`）；文件没路径 / 不在 TAS 目录里 → `toast` 提示「先保存到 TAS 目录」并中止。
2. 读 `<实例>/ModLoader/Configs/BallanceTAS.cfg`。读不到、或读到的不是 BallanceTAS 的配置（没有 `TAS` / `Startup` / `OSD` 分区）→ `toast` 提示「没找到配置，请先在游戏里启动一次这个 mod」并中止。
3. `planPlayback()` 算出要改哪几项：

| 分区 | 名字 | 写成 | 含义 |
| --- | --- | --- | --- |
| `TAS` | `Enable` | `1` | TAS 功能 |
| `Startup` | `Enabled` | `1` | 启动时启用 TAS 项目 |
| `Startup` | `AutoLoad` | `1` | 启动时自动播放 |
| `Startup` | `Project` | 文件名去掉 `.tas` | 要播放的项目 |
| `Startup` | `Level` | `Level_01` … `Level_13` | 启动后自动进入的关卡（2.0.0-beta.1 新增） |
| `TAS` | `SkipRenderUntilFrame` | 「播放」= 编辑器当前帧；「从头播放」= `0` | 这一帧之前不渲染（快进），见下 |

   游戏里 `Project` / `Level` 是单选列表（mod 调 `BML_SetConfigPropertyChoices`），但写进 cfg 仍是普通的 `S` 字符串；`Level` 的「None」= 不自动进关，一键播放不会写它。`TAS.AutoRestart`（beta.1 默认开）不动。

4. **只有某个开关当前不是期望值时**才弹确认框（标题「一键播放需要打开自动加载」，正文逐行列出现值与新值，如「启动时自动播放：关 → 开」「启动项目：SR_01_1.16.726」），按钮 `[取消]` / `[打开并播放]`。只改项目名 / 关卡（三个开关本来就都开着）就直接写，不打扰用户。取消 = 什么都不写、也不启动。
5. 写配置走 `backend.saveModConfig`；`applyPlayback()` 只改上表那几项（文件里缺的项：布尔补 `B`、项目名 / 关卡补 `S`，同时把分区登记进 `categories`，否则后端会整段跳过这个分区）。
   - ⚠️ 后端写盘是「整文件重排重写」：分区**内**的条目、描述、注释、缩进逐字保留，但**分区顺序会变**、文件首行那句 `# Configuration File for Mod: ...` 会**丢**（既有 `save_mod_config` 的行为，在「模组配置」页改任何 mod 配置都一样，不是这个功能引入的）。
6. 游戏在跑（游戏区域是 `running`，或者有任何 `Player.exe` 进程）→ 弹第二个框「TAS 配置只在游戏启动时读取，需要重启游戏才能生效。要关闭当前游戏并重新启动吗？」`[取消]` / `[重启并播放]`；确认后杀进程并清掉运行状态。没在跑就直接启动。
   - 摆在区域里的游戏**必须走 `stopGame()`**（先把状态切回 `idle` 再 detach + kill）。只按 pid 杀的话 `game` 还是 `running`，400ms 的存活轮询会看到旧 pid 没了，转头把**新**启动那个游戏的窗口 detach 掉。
   - 主窗口启动的游戏（TAS 窗口是独立 webview、拿不到它的 pid）现在也能发现：播放前按映像名查 `Player.exe`（见 §8.1）。
7. `startGame()` 启动游戏并把窗口摆进右上区域（见 §8.1；编辑器窗口不一定加载过实例数据，所以先 `loadInstance()` 兜一下），最后 `toast.success`「已把 BallanceTAS 的启动项目设为 `<项目名>`，正在启动游戏…」。

两个确认框共用一套「state + resolve」（`askPlay()` / `answerPlay()`），弹框前先 `hideGameWindow()`（游戏窗口压在 WebView 上面，HTML 弹窗盖不住它），取消时再 `showGameWindow()` 摆回去；`Esc` 或点遮罩按「取消」处理；弹窗期间 `W`/`S`/`A`/`D` 等快捷键不再打到时间轴上（`isTypingTarget()` 认得 `role="alertdialog"`）。`toast` 由 App 那份 `Toaster` 渲染（与 `GlobalDialogHost` 同一处）。

> ⚠️ 弹窗上的 `z-[51]` 不能删：同一个 radix 实例「刚关掉又被重新打开」（取消后再点一次、或上一个框答完立刻弹下一个框）时，它会把遮罩插到内容**后面**，两者同为 `z-50` → 新弹窗被自己的遮罩盖住、按钮**点不动**（DOM `.click()` 还能用，真实鼠标不行）。把内容提到 `z-51` 就与 DOM 顺序无关了。

### 8.0 播完把设置改回去 / 正常启动的保底

一键播放会把 BallanceTAS 改成「启动就自动进关卡回放」。不改回去的话，之后**正常开游戏也会自动进关卡、回放录像**。

- **记下来**（`src/tas/play.ts`）：写配置时把改了的每一项的原值记进 localStorage（`rockoon-tas-cfg-restore`，编辑器崩了 / 关了也不丢）；原来没有的项记成 `undefined`，改回去时删掉。连着播好几次只保留**最早**的原值。纯逻辑自测：`.local-logs/tas-restore-test.ts`。
- **改回去**（`src/services/tasGuard.ts` 的 `restoreTasConfig`）：只在**没有任何 Player.exe 在跑**时才动（BML+ 退出时可能把内存里的配置写回文件）。时机：停止（等进程退干净之后；重启流程里不改，那时刚写好新配置）、游戏自己退出、关编辑器时选「一起关掉」、编辑器打开时、正常启动游戏前。关编辑器时选「保留运行」就留到下一个时机。
- **正常启动的保底**（`confirmTasAutoplayOff`，主页「启动游戏」和自制地图都会调）：先试一次改回去；BallanceTAS 若仍然 `TAS.Enable` + `Startup.Enabled` + `Startup.AutoLoad` 全开，弹框「关闭自动播放并启动 / 保持开启并启动」，关掉对话框 = 不启动。「关闭」只把 `Startup.AutoLoad` 写成 0，别的不动。TAS 编辑器自己的启动不走这个。

### 8.1 游戏区域（右上）

游戏不是另开在别处，而是**摆进编辑器右上那块 1:1 的黑框**里，一边看回放一边改时间轴。前端在 `TasEditorWindow`（`startGame` / `stopGame` / `hideGameWindow` / `showGameWindow`），Rust 在 `src-tauri/src/commands/embed.rs`（`attach_game_window` / `move_game_window` / `detach_game_window` / `game_window_info`，包装在 `backend.*GameWindow`）。

- **状态**：`idle` → `launching`（等游戏窗口出来）→ `running` →（停止）`stopping` → `idle`。按钮都在左侧「回放」分区。
- **Ballance 不支持多开**：`kill` 只是发出 `taskkill`、不等它结束，`Player.exe` 往往还要再活一会儿；这时候再启动会出问题（实测一次：杀旧进程和起新进程在同一秒，随后 Rockoon 自己也异常退出了）。所以：
  - 「停止」进入 `stopping`：detach + kill，然后每 200ms 用 `find_processes("Player.exe")`（`tasklist` 按映像名）查一次，**所有 Player.exe 都没了**才回 `idle`（最多等 10 秒，超时提示去任务管理器结束）。`launching` / `stopping` 期间两个播放按钮都不能点。
  - 播放前也查一遍 `Player.exe`：不只是自己摆进来的那个，主窗口启动的、上次没退干净的也算 —— 有就弹「需要重启游戏」，确认后全部结束并等它们退干净再启动。
  - 游戏结束（停止 / 自己退出）都会清掉 app store 里的 `runningInstancePid`，否则下次播放会以为游戏还在跑。
- **启动**：`launchInstance({ args: ["-w", W, "-h", H], keepMainWindowVisible: true, highPriority: true })`。
  - 分辨率必须在启动时用 `-w/-h` 定死：游戏的渲染上下文是固定尺寸，事后改窗口大小只会拉伸画面。
  - `keepMainWindowVisible`：不因「启动时隐藏主窗口」偏好把窗口藏走。
  - `highPriority`：`process.execute` 新增的 `args` / `high_priority` 参数，后者用 `SetPriorityClass(HIGH_PRIORITY_CLASS)`。
  - 拿到 pid 后 `attachGameWindow(pid, 区域物理像素 rect)`；Rust 每 50ms 找一次窗口，最多等 30s。
- **跟随**：`running` 期间每 400ms 轮询一次区域的 `getBoundingClientRect()`（拖分栏、缩放窗口都只体现在这里），变了就 `moveGameWindow`；同时 `backend.check(pid)`，进程没了就 detach 回空态。
- **关窗**：游戏还在跑时拦下 `onCloseRequested`，问「一起关掉 / 保留运行 / 取消」；确认后 `detach` →（可选 `kill`）→ `win.destroy()`。`destroy` 需要 `capabilities/default.json` 里的 `core:window:allow-destroy`，没有它窗口会彻底关不掉。

> **游戏窗口怎么“摆进”那块区域（2026-10-09 定论，实现在 `src-tauri/src/commands/embed.rs`）**：**不 reparent**。只做三件事：
> 1. 剥掉标题栏 / 边框（`WS_POPUP|WS_CAPTION|WS_THICKFRAME|WS_SYSMENU|WS_MINIMIZEBOX|WS_MAXIMIZEBOX`）。剥完是**无边框顶层窗口** → 「窗口 rect == 客户区 rect」，可以直接按区域坐标摆位。
> 2. 把 **owner 设成 TAS 编辑器窗口**（`SetWindowLongPtrW(child, GWLP_HWNDPARENT, editor)`，不是 `SetParent`）：owned window 始终压在 owner 上面、**owner 最小化时一起隐藏、复原时一起回来**、owner 销毁时一起销毁（用户要求最小化/复原必须带动游戏窗口，靠的就是这条）。
> 3. `SetWindowPos(child, HWND_TOP, 屏幕坐标, 区域尺寸)`。
>
> 为什么不用 `SetParent`（同一台机实测，编辑器真前台 + `WindowFromPoint(区域中心)` 已确认游戏是输入目标 + `SendInput` 注入真实鼠标输入）：子窗口化后鼠标一划过游戏窗口，**游戏主循环就停摆**（进程 CPU `0.98 核 → 0.10~0.16 核`、`PrintWindow` 平均亮度 0、不呈现），鼠标一停立刻恢复；改成顶层窗口后同一注入下 **0.92 核、亮度 153、正常渲染**。注意 `SetCursorPos` 合成的移动**不产生 `WM_INPUT`**，用它无论怎么扫都测不出来，必须用 `SendInput`；另外「`WindowFromPoint(区域中心)` 必须是游戏窗口」这条前置断言不能省（编辑器不在最前时那块下面是 WebView，注入全被吃掉，看起来就像“测不出来”）。

### 8.2 只看不碰（鼠标不被游戏吃掉）

两个原因叠在一起，要分别处理：

1. **游戏在前台时会藏指针**（DirectInput 独占 + `ShowCursor(FALSE)`）。游戏刚启动时会自己抢前台。
   → 摆位期间默认**只看不碰**：给游戏窗口加 `WS_EX_LAYERED | WS_EX_TRANSPARENT | WS_EX_NOACTIVATE`（`SetLayeredWindowAttributes` alpha 255，画面不变），点击穿透到编辑器、游戏窗口不会被激活。attach 后用 `AttachThreadInput` 挂到前台线程再 `SetForegroundWindow(编辑器)` 把前台还回来（普通的 `SetForegroundWindow` 会被前台锁拦下）；看门狗发现游戏又抢回前台时同样还回去。
2. **藏掉的指针不会自己回来，而且会「传染」到整个编辑器**。游戏失去前台后不还原 `ShowCursor` 计数；而我们把游戏窗口的 owner 设成了编辑器 —— **跨进程 owner 会让两边线程共用输入队列**，`ShowCursor` 的计数就在队列上，于是指针在整个编辑器里都不见了（速度控件点不到），换到别的程序上又正常。只做第 1 条时就是这个症状（用户实测：开始播放后鼠标消失）。
   → `RockoonIO`（只在编辑器启动的游戏里，靠 `ROCKOON_TAS_FPS` 判断）每约 50ms 检查一次：游戏**不在前台**就把本线程的显示计数抬回恰好 0（`KeepCursorVisibleWhenInactive`）。游戏在前台（「操作游戏」打开）时不管，游戏照常藏指针。
   - 不能靠去掉 owner 解决：最小化/复原联动、始终压在编辑器上面都靠它（§8.1）。

- 需要给游戏按键时（BallanceTAS 的 F4~F8 HUD、停止键）点顶栏的「操作游戏」（`set_game_window_interactive(true)`）：去掉那三个样式并把前台交给游戏 —— 这时鼠标会被游戏捕获，Alt+Tab 回编辑器再点一次关掉。
- 实测（`.local-logs/tas-cursor-probe.ps1`，真机，会真的进关卡回放）：游戏先当 1.5 秒前台 → owner 设成 Rockoon 窗口 → 只看不碰 → 还前台，之后每秒在 游戏区域 / 宿主窗口 / 远处 三点读 `GetCursorInfo`。修复前：游戏区域与宿主窗口一直 `flags=0, hCursor=0`（远处正常）；修复后 40 秒内（含进关、开始回放）三点都显示。⚠️ 只测「游戏从没当过前台」的情形是测不出来的（第一版就是这么漏掉的）。

### 8.3 回放调速（播放中随时可调）

「Bandicam 式」限速，**不碰游戏逻辑**：只在每个逻辑帧末尾等到下一帧该开始的时刻。Ballance 是单线程主循环，TAS 每个逻辑帧消耗一帧录像，所以**回放速度 = 目标帧率 / 录像帧率**，录像里的 deltaTime（游戏内时间）完全不受影响。等待放在 Rockoon 自带的 `RockoonIO.bmodp` 里（BML+ 本来就会加载它），不做外部注入。

- **模组**（`src-bmodp/src/FramePacer.*` + `RockoonIO::OnProcess`）：只有带 `ROCKOON_TAS_FPS` 环境变量启动（= TAS 编辑器启动的）才开启，普通启动不受影响。开启后：
  - 建共享内存槽 `Local\RockoonIO.FrameLimit.<pid>`：`{ u32 magic "RKFL", u32 version 1, f32 targetFps, f32 measuredFps }`（两边布局必须一致）。
  - 每帧把 Virtools 的限速设成 `CK_FRAMERATE_FREE`（否则 BML+ 的 `SetMaxFrameRate`（默认 600）/ 垂直同步会在上面再压一道，高倍速跑不上去；BML+ 改配置会重设，所以每帧检查）。
  - `timeBeginPeriod(1)` + 固定节拍：`next += period`，`Sleep` 到差 1.5ms 再自旋。目标帧率变了、或落后超过 `max(4 帧, 100ms)`（载入关卡这类真卡顿）才从当前时刻重新起拍；更小的调度抖动会追回来 —— 门槛原来是 4 帧，240 fps 时实测掉到 232。
  - **不渲染的帧不限速**：`RockoonIO::OnRender` 记一笔，`OnProcess` 里连续 2 帧都没渲染就 `Wait(unpaced = true)`。这是给 BallanceTAS 的 `SkipRenderUntilFrame` 用的（「从当前帧播放」的快进段），否则快进也会被压在目标帧率上。
  - 约每 0.5 秒把实测帧率写回 `measuredFps`。
- **Rust**（`src-tauri/src/commands/frame_limit.rs`）：`set_game_frame_limit(pid, fps)` / `game_frame_limit(pid)`，按 pid 打开槽、校验 magic/version、读写后立刻解除映射。槽还没建好（游戏在载入）就报错，调用方重试。
- **编辑器**：游戏区域顶栏的速度**滑条**（`Slider`，按档位走：0.1× ~ 16×，最右一档 = 不限速，档位在 `PLAY_SPEED_STOPS`）+ 旁边的倍率读数（点一下恢复 1×；下面一行小字是实测帧率，没在跑时是目标帧率）。倍率存偏好 `playSpeed`（相对录像帧率，所以换个帧率不同的录像也还是同一倍速；不在档位上的旧值按对数距离显示最近一档）。启动时初始帧率随 `ROCKOON_TAS_FPS` 带进去；拖动中每一档都 `setGameFrameLimit`，没写进去（`sentFpsRef !== targetFpsRef`）就由 400ms 的存活轮询重发，同一个轮询顺便读回实测帧率。
- 实测（真机，目标 → 实测，每档 3 秒后读）：60 → 60、120 → 120、240 → 240、480 → 480.2、960 → 963.3、0（不限速）→ 约 2035；改目标后下一次读数就已生效。
- **构建模组**：`pnpm build:bmodp`（`src-bmodp/build.ps1`，要 CMake ≥ 4.0 在 PATH 上，本机是 `D:\Codes\ctools\cmake-4.1.1-windows-x86_64\bin`；VS 2022 Build Tools、Win32）。产物会复制到 `src-tauri/resources/builtin-mods/`，Rockoon 每次载入实例都会把它装进 `ModLoader/Mods/`。⚠️ dev 模式下装的是 `src-tauri/target/debug/resources/` 里那份（构建时才同步），只改了模组没动 Rust 的话要手动同步一下，否则下次载入实例会把旧版装回去。
