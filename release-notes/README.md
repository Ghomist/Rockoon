# 更新日志（release notes）

**每次发布新 release 之前，都必须在这个目录下写一份 `<版本>.md`**，否则 CI 会直接拒绝发布
（见 `.github/workflows/release.yml` 的「读更新日志」步骤）。版本号必须和
`src-tauri/tauri.conf.json` 里的 `version` 完全一致 —— 文件名就是版本号。

为什么要强制：这份文件会变成两处的正文 ——

1. GitHub release 的正文；
2. release 里 `latest.json` 的 `notes` → 下载站镜像原样透传 → **启动器「发现新版本」弹窗里显示的更新内容**。

## 格式

只写这次实际改了什么，三段里没有的就不写。

```md
## 新增
- 一键播放支持自制地图

## 修改
- 时间轴现在可以拖拽调整

## 删除
- 移除了旧的导入进度弹窗
```

约定（都很宽松，写惯了可以少写点）：

- 标题写 `## 新增`、`**新增**`、或者单起一行「新增」都认。裸标题只认「新增/修改/修复/删除/移除」这几个词（可以带冒号，如「新增：」）—— 免得正文里一句短话被当成标题。
- 「修复」按「修改」显示；英文界面显示 Added / Changed / Removed。标题认不出来就原样显示。
- `-` 或 `*` 开头是条目（缩进 2 格算嵌套），`1.` 开头是有序条目，`>` 引用，`---` 分隔线，``` 围栏代码块。
- 条目里可以用行内 markdown：`代码`、`**加粗**`、`*斜体*`、`~~删除线~~`、`[文字](https://example.com)`（只渲染 http/https/mailto，其它原样显示）。
- 弹窗里是**真渲染**（标题加粗分段、列表带要点、代码用等宽底纹），不是原样打印 markdown —— 解析器是 `src/utils/update-notes.ts`，渲染是 `src/components/UpdateNotes.tsx`，只支持这些写法，别指望表格、图片、HTML。
- `<!-- -->` 注释不会显示出来（写给维护者的话可以塞里面）。
- 条目一句话说清「改了什么」，别提内部文件名。

示例模板见 `_TEMPLATE.md`（`_` 开头不会被发版检查当成版本文件）。
